# 【要件定義＆制作指示プロンプト】地域アマチュアフットサルリーグ「ONE LEAGUE」公式Webサイト / LP

---

## 1. プロジェクト概要

* **プロジェクト名:** ONE LEAGUE（ワンリーグ）
* **対象:** 地域密着型のアマチュア向けフットサルリーグ
* **フェーズ（最重要前提）:**
  * **【初年度（現在）】:** 新規立ち上げリーグ。チーム集めはWebではなく「口コミ・紹介」で実施。
    * **サイトの主目的:** 参加チーム同士で **「試合日程・対戦カード・結果・順位表がスマホでサクサク共有できる公式運営ポータル」**。
    * 口コミで声をかけたチームにURLを見せた際、「しっかりした公式リーグ感（信頼性・実体感）」を醸成する。
  * **【来年度以降（フェーズ2）】:** 初年度の実績データ（順位表、試合写真、参加チーム）をソーシャルプルーフ（社会的証明）とし、Web集客・新規チーム公募用LPへシームレスに拡張する。

---

## 2. ターゲットユーザーと要件定義

### ターゲットA：既存参加チームの選手・代表者（Primary / Daily Use）
* **アクセス動機:** 「次節の相手と会場時間は？」「昨日の試合結果と順位は反映されたか？」
* **閲覧環境:** ほぼ100% スマートフォン（試合直前、移動中、飲み会など）
* **要求UI:** スクロールを強いる縦長LPはNG。ファーストビュー直下で「順位・日程・結果」に1タップでアクセスできること。

### ターゲットB：口コミで紹介されたチーム・参加検討者（Secondary / Trust）
* **アクセス動機:** 「誘われたけどどんなリーグ？」「レベル高すぎてガチ勢に怒られないか？」「ルールや費用は？」
* **要求UI:** エンジョイ志向の安心感、フェアプレー精神、明瞭な規約・費用体系の提示。

## 3. ベンチマーク・デザインリファレンス

* **順位表・日程のUI参考:**
  * **[Tournify (tournifyapp.com)](https://www.tournifyapp.com/)** / **[Score7 (score7.io)](https://score7.io/)**
  * 盗むべき要素: スマホで横スクロール崩れしない「カード型・アコーディオン型順位表」、タブ切替（`[順位表]` / `[次節日程]` / `[過去結果]`）。
* **トーン＆マナー・安心感の参考:**
  * **[エフチャンネル (f-channel.net)](https://www.f-channel.net/)**
  * 盗むべき要素: 「エンジョイ志向」「スライディング禁止・リスペクト精神」「敷居の低さと清潔感」。
* **公式感・信頼性の参考:**
  * **[F7SL 日本ソサイチ連盟 (football7society.jp)](https://football7society.jp/)**
  * 盗むべき要素: 公式リーグとしての整ったレギュレーション・参加チーム一覧の掲載形式。

## 4. 推奨サイト構造（シングルページ Web / LP）

スマホファーストで、1ページ完結型（アンカーリンク遷移）の全5セクション構成。

```text
┌────────────────────────────────────────────────────────┐
│ Header: リーグロゴ ＋ [順位表] [日程] [ルール] [チーム] [問合せ]  │
├────────────────────────────────────────────────────────┤
│ Section 1: Hero & Quick Navigation                     │
│  - リーグコンセプト・開催地域・シーズン概要                    │
│  - 最速アクセスボタン: [最新順位表を見る] [今節の日程]        │
├────────────────────────────────────────────────────────┤
│ Section 2: League Dashboard (最重要コアモジュール)      │
│  - タブ切替 UI:                                        │
│    ①【順位表】順位 / チーム名 / 勝点 / 得失点 (タップで詳細) │
│    ②【日程・対戦カード】開催日・会場・キックオフ時間・組合せ   │
│    ③【試合結果】過去節のスコア一覧                           │
├────────────────────────────────────────────────────────┤
│ Section 3: League Regulations & Fairplay (信頼・安心)  │
│  - エンジョイルール規定（スライディングタックル原則禁止等）      │
│  - 審判体制（専任審判配備）、公式球・ビブス用意               │
│  - 会場アクセス（駐車場・更衣室情報）、雨天時の中止連絡フロー    │
├────────────────────────────────────────────────────────┤
│ Section 4: Participating Teams (参加チーム紹介)        │
│  - 初年度参加チームのカード一覧（チーム名、ロゴ/写真、コメント） │
│  ※初期メンバーのロイヤルティ向上と、コミュニティ感の演出       │
├────────────────────────────────────────────────────────┤
│ Section 5: Contact & Next Season Waitlist (来年度への布石)│
│  - 運営問い合わせ窓口（公式LINE連携ボタン / 簡易フォーム）   │
│  - 来年度シーズン参加・見学のウェイティングリスト（プレ登録）   │
└────────────────────────────────────────────────────────┘
```

## 5. 実装・技術仕様ガイドライン

### ① モバイルファーストUI
* テーブルの横幅圧迫を回避すること。
  * デスクトップ: `順位 | チーム | 勝点 | 試合数 | 勝 | 分 | 負 | 得点 | 失点 | 得失差`
  * モバイル: `順位 | チーム名 | 勝点 | 得失差` を1行表示し、タップで試合詳細（勝/分/負）が展開するアコーディオンまたはカード型を採用。

### ② データ管理・運用の保守性（重要）
* 毎週のスコア更新がHTMLベタ書き修正だと運用が破綻します。
* 以下のいずれかの軽量アーキテクチャで実装すること：
  * **推奨案A:** Googleスプレッドシートをマスタとし、CSV/JSON API経由（またはGAS）でフロントにフェッチ・描画。
  * **推奨案B:** `data/league-data.json` などの単一データファイルを更新するだけで、順位・日程・結果がリアクティブに再計算・描画される構造。
  * **推奨案C:** 初年度は `Tournify` や `Score7` などの外部埋め込みウィジェットを活用し、開発コストをゼロにする。

### ③ デザインシステム
* **トーン＆マナー:**
  * スポーティかつクリーン（ネイビー/ディープブルー ＋ アクセントにエナジーグリーンやイエロー）。
  * ガチガチの競技志向ではなく、社会人が気持ちよく週末にプレーできる「洗練されたアマチュアスポーツ感」。
* **フォント:** 可読性の高いサンセリフ（Inter / Noto Sans JP）。数字は等幅（tabular-nums）または視認性の高いウェイトを採用。
